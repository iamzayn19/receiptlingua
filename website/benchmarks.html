Benchmarks

These numbers are copied directly from BENCHMARKS.md in the repository, not restated or rounded to look better. If the two ever disagree, BENCHMARKS.md is the source of truth — this page should be re-checked against it.

Scope, read this first: all data below is from a real, executed run of 350 synthetic cases (later re-measured on a focused 420-case RTL run after bug fixes) generated by the project's own synthetic receipt generator — not real-world receipt photos, and not yet the eventual 10,000+ case target. This is an honest first read on pipeline behavior, not a final accuracy claim.

RTL fix: before / after (420-case focused re-run)

The original run measured Arabic/Hebrew CER above 1.0 (more character errors than the ground truth has characters) — a broken pipeline, not "needs improvement." Three real bugs were found and fixed (missing bidi/reshaping in the synthetic generator, tofu-box digit glyphs in the Arabic/Hebrew fonts, and Tesseract's own visual-order RTL output never being corrected back to logical order).

CER (character error rate) improved substantially for Arabic and Hebrew, and CER is still meaningfully worse than English's ~0.10 — reported honestly, not as a finished result. The residual gap is most likely Tesseract's tessdata_fast ara/heb models being genuinely weaker than eng's, not a further pipeline bug; closing it likely needs tessdata_best packs and/or a non-Tesseract engine comparison. See BENCHMARKS.md for the full root-cause writeup.

What's excluded from this run

  • PaddleOCR — deliberately excluded from this run; the sidecar's per-call startup cost dominates wall time for small batches and a fair per-case number needs a warm/reused sidecar, which the harness doesn't do yet.
  • Real-world receipt photos — all cases are synthetically generated; no photographed receipts are in this dataset yet.
  • tear_missing_section / curved_page_dewarp degradations — deferred, no convincing implementation built yet.
