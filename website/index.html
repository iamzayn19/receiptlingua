ReceiptLingua

Offline-first, multilingual receipt OCR — no paid API required.

Status: pre-0.1, early development. Nothing here is published to PyPI/npm/RubyGems yet. This site documents real, current progress, not a marketing preview — numbers below come straight from the repository's own BENCHMARKS.md.

What it solves

Receipt OCR tools tend to assume clean, English-language, well-lit photos. Real receipts are frequently faded, crumpled, thermal-printed, torn, rotated, badly photographed, or in a language/script the tool was never tuned for. ReceiptLingua targets that harder case directly:

Offline-first

Runs fully offline after model download — no per-call API fees, no sending receipt photos to a third-party cloud service by default.

Multilingual by design

Tracks a language-support matrix across dozens of languages and scripts, including right-to-left scripts (Arabic, Hebrew), with an honest distinction between "the model can technically produce output" and "verified to work well on real receipts."

Structured extraction with evidence

Merchant, date, totals, and line items are extracted with provenance back to the source text, not opaque black-box output.

Three ecosystems, one engine

A single Python OCR/extraction engine, wrapped by a native TypeScript/npm client and a Ruby gem, sharing one JSON wire protocol.

Installation

Python

pip install receiptlingua
from receiptlingua import ReceiptOCR

ocr = ReceiptOCR()
result = ocr.scan("receipt.jpg")
print(result.full_text)

JavaScript / TypeScript

npm install receiptlingua
import { ReceiptOCR } from "receiptlingua";

const ocr = new ReceiptOCR();
const result = await ocr.scan("receipt.jpg");

Ruby

gem install receiptlingua
require "receiptlingua"

ocr = ReceiptLingua::ReceiptOCR.new
result = ocr.scan("receipt.jpg")

None of these packages are published yet (pre-0.1, see the status banner above) — this is the API surface as implemented in the repository today.
